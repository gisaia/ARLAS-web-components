## 7. Questions ouvertes et hypothèses d'intégration

1. **Type d'instance de carte par panneau (`ARLAS-maplibre` vs wrapper MapLibre GL JS dédié)** : Faut-il instancier dans chaque `MapPanelComponent` une carte `ARLAS-maplibre` (réutilisation des mécanismes ARLAS existants, sous réserve de pouvoir désactiver les contrôles individuels RF-14, verrouiller Mercator RF-15 et supporter 2 à 4 instances simultanées sans état global partagé) ou un wrapper léger dédié autour de `maplibregl.Map` ?
2. **Architecture et périmètre de la lecture radiométrique (`RadiometricProbeAdapter` remis en cause — RF-21 / CA-10)** : Le composant de lecture radiométrique existant n'est pas défini dans `ARLAS-web-components` mais dans une **application parente**, et **ne couvre que les COG** (pas les autres visualisations raster). Trois points doivent être arbitrés :
   * *Localisation / couplage* : faut-il rapatrier/généraliser ce composant dans `ARLAS-web-components`, ou inverser la dépendance en exposant dans `arlas-visualisation-comparator` un point d'extension (`InjectionToken` de service de sonde et/ou `ng-template` personnalisé fourni par l'application parente) ?
   * *Visualisations raster non-COG* : quel est le comportement attendu sur les visualisations ne supportant pas l'interrogation radiométrique (masquage de la zone de sonde dans la légende, mention explicite ou affichage de `« — »`) ?
   * *Opacité 0 % et multi-panneaux* : garantir que la solution retenue opère sur coordonnées géographiques partagées `[lng, lat]` indépendamment du rendu WebGL afin de fonctionner à opacité globale 0 % (CA-10).
3. **Réutilisation du sélecteur de fond de carte existant (`BasemapComponent`)** : Confirmer si le composant de gestion de fond de plan d'ARLAS peut être encapsulé directement dans `SharedMapControlsComponent` ou si un sélecteur léger autonome est préférable pour éviter tout couplage.
4. **Comportement réseau sur les tuiles raster manquantes (NoData / 404)** : Clarifier si les serveurs de tuiles COG (ex. TiTiler) retournent un code HTTP 404 sur les tuiles hors emprise (qui doivent être ignorées silencieusement sans déclencher l'état d'erreur du panneau RF-25) ou du PNG transparent HTTP 200.
5. **Intégration npm et bundling `ng-packagr` de `maplibre-gl-swipe`** : Valider l'ajout de la dépendance `maplibre-gl-swipe` (`^0.14.0`, MIT, ESM/CJS) dans les `dependencies` / `allowedNonPeerDependencies` (ou `peerDependencies`) du package `projects/arlas-visualisation-comparator`, ainsi que la modalité d'inclusion de `maplibre-gl-swipe/style.css` selon les conventions SCSS de la bibliothèque.
6. **Récupération des géométries, métadonnées et visualisations en cas d'accès direct par route Angular avec `initialState` (`ComparisonState.itemIds` insuffisant seul — RF-27, RF-37, RF-38, RF-39)** : Si la vue de comparaison est ouverte directement via une route Angular dédiée alimentée par un `initialState` (sans sélection préalable en mémoire dans l'écran appelant), la seule liste `itemIds: readonly string[]` de `ComparisonState` (01 § 4.3) ne suffit pas à `arlas-visualisation-comparator` (agnostique du backend ARLAS-server / STAC) pour reconstituer les cartes du volet latéral, les emprises et les visualisations — ni à un résolveur en contexte multi-collections sans le nom de la `collection`. Trois options d'architecture restent à arbitrer :
   * *Option A — Snapshot complet auto-porteur* : sérialiser directement `items?: readonly ComparisonItem[]` (géométries, métadonnées UTC, vignettes et descripteurs de visualisations) dans `ComparisonState`, rendant `[items]` optionnel à la réouverture (avec un point d'attention sur la taille du JSON et l'expiration éventuelle d'URLs signées).
   * *Option B — Références qualifiées + résolveur parent* : stocker `itemRefs?: readonly { id: string; collection?: string }[]` dans `ComparisonState` et confier à l'application parente (en amont vers `[items]` ou via un `InjectionToken<ComparisonItemResolver>`) le rechargement des `ComparisonItem[]` frais depuis le catalogue ARLAS/STAC (garantissant droits et jetons à jour).
   * *Option C — Hybride (snapshot embarqué + surcharge fraîche)* : embarquer `items?: readonly ComparisonItem[]` (avec `collection?: string`) dans `ComparisonState` pour une autonomie immédiate, tout en permettant à l'application appelante de surcharger/rafraîchir ces items via `[items]` ou un résolveur optionnel.
